# Интерактивный атлас архитектуры

Откройте [index.html](index.html) в браузере. Это один самодостаточный HTML:
работает через `file://`, не требует backend, CDN, интернета или credentials.
Для удобного просмотра в IDE можно запустить `make architecture-serve` и
открыть `http://127.0.0.1:8099/`.

Атлас показывает реализацию в рабочем дереве, а не состояние запущенного
production. Identity и Notification определяются по service descriptors.
Целевая модель, ещё не реализованные producers и consumers отмечены отдельно.
Legacy Go bootstrap и development notification sink не являются доменными
сервисами и не входят в перечень активных сервисов.

## Навигация

- **Карта системы:** компоненты и направления связей; клик по узлу или стрелке
  открывает детали. Масштаб изменяется кнопками; большая схема прокручивается.
- **HTTP-запросы:** все активные операции, path/query/header parameters,
  request body, обязательность, ограничения, ответы, headers и security.
  Вложенные схемы доступны в таблицах и полном JSON. Probes выделены отдельно
  внутри каждого сервиса и не показаны как публичные gateway routes.
- **События:** точные subjects, envelope, payload, producer и consumers
  с отдельным статусом реализации. Группы — по producer; после выбора сервиса
  можно оставить только публикуемые или получаемые им события.
- **Сценарии:** последовательность обработки и транзакционные границы;
  группы и фильтр — по владельцу сценария, общие сценарии вынесены в
  «Инфраструктуру». Межсервисные шаги остаются видны целиком.
- В HTTP, событиях и сценариях есть собственная строка фильтра по сервису
  со счётчиками. «Все сервисы» возвращает полный список; фильтр сохраняется
  при переходе между разделами и в URL. Направление событий — только в
  ссылках раздела событий.
- **Таймауты и правила:** source-linked defaults, production overrides,
  retries, TTL, лимиты, расписания и явно неизвестные значения.
- Поиск `/` работает по ручкам, полям схем, событиям, сценариям и параметрам.
  Выбранные раздел, элемент и фильтр сохраняются в URL fragment.
- Ссылки на исходники открывают встроенный снимок с подсветкой строки.
  Примеры cURL используют placeholders и не выполняются из интерфейса.

## Сборка и проверка

Из корня репозитория, Python 3.10+ и Node.js для проверки JavaScript:

```bash
make architecture-build
make architecture-check
```

Первая команда создаёт изолированный Python venv в игнорируемом
`.cache/architecture-explorer-venv` и устанавливает закреплённый PyYAML.
Для уже подготовленного окружения доступны прямые команды:

```bash
.cache/architecture-explorer-venv/bin/python docs/architecture/explorer/build.py
.cache/architecture-explorer-venv/bin/python docs/architecture/explorer/build.py --check
.cache/architecture-explorer-venv/bin/python -m unittest discover \
  -s docs/architecture/explorer/tests -p 'test_*.py'
node --check docs/architecture/explorer/app.js
node --test docs/architecture/explorer/tests/test_ui.cjs
```

`--check` не меняет файлы и завершается ошибкой при устаревшем `data.js` или
`index.html`. Выход детерминирован: fingerprint считается по содержимому
источников; время сборки и изменяющийся Git HEAD в него не входят.
CI выполняет эту проверку и тесты генератора.

## Источники и добавление сервиса

Для агентов в репозитории есть
[скилл architecture-map](../../../.agents/skills/architecture-map/SKILL.md):
добавление сервиса, исправление существующей карты и проверка результата.

1. Добавьте обычный `backend/services/<id>/service.yaml` и callee-owned
   OpenAPI-контракт, обновите канонические YAML в `docs/architecture/model/`.
   Генератор автоматически обнаружит descriptor, ручки и probes. Один только
   roadmap-контракт не переводит сервис в статус «реализовано».
2. Добавьте `details/<id>.json` с фактическими сценариями и параметрами. Каждый
   факт и шаг ссылается на `{ "path": "<repo-relative>", "line": 123 }`.
   Неизвестный timeout указывайте как неизвестный; не подменяйте его timeout
   соседнего компонента. Значения defaults и overrides различайте явно.
3. Пересоберите атлас, проверьте сценарии в браузере и закоммитьте исходники
   вместе с обоими сгенерированными файлами.

Минимальный дополнительный файл:

```json
{
  "serviceId": "example",
  "facts": [
    {
      "id": "example-request-timeout",
      "label": "Таймаут запроса",
      "value": "Не задан явно",
      "description": "Проверить вместе с реализацией transport.",
      "source": { "path": "backend/services/example/service.yaml", "line": 1 }
    }
  ],
  "flows": [
    {
      "id": "example-read",
      "title": "Чтение данных",
      "operationIds": ["readExample"],
      "description": "Фактический путь операции.",
      "steps": [
        {
          "node": "example",
          "label": "Обработка запроса",
          "detail": "Проверка доступа и чтение принадлежащих сервису данных.",
          "source": { "path": "backend/services/example/service.yaml", "line": 1 }
        }
      ]
    }
  ],
  "operationNotes": {
    "readExample": { "flowId": "example-read", "notes": ["Уточнение поведения."] }
  }
}
```

`build.py` проверяет пути источников, номера строк, operation IDs, узлы
сценариев, ссылки `flowId` / `nextFlows`, уникальность facts и локальные `$ref`.
Необязательный `nextFlows` содержит IDs сценариев асинхронного продолжения.
Источники встраиваются только из разрешённых
каталогов и типов файлов; `.env`, ключи и state не читаются.

При изменении кода CI обнаружит устаревший снимок. Генератор **не доказывает**
актуальность написанного человеком пояснения: вместе с пересборкой нужно
сверить затронутые facts/flows с кодом. OpenAPI, service descriptors и YAML
модель остаются источниками истины; HTML — их навигационное представление.

## Файлы

- `build.py`, `requirements.txt`, `tests/` — генератор и его проверки.
- `template.html`, `style.css`, `app.js` — интерфейс без runtime-зависимостей.
- `details/*.json` — пояснения с точными ссылками на реализацию.
- `data.js` и `index.html` — сгенерированные артефакты; вручную не редактировать.

Публикация не требуется. HTML содержит технические исходники и предназначен
для той же аудитории, что и репозиторий; расширение аудитории — отдельное действие.
