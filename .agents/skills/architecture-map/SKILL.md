# Обновление карты архитектуры

Результат — актуальный `docs/architecture/explorer/index.html`, согласованный с
контрактами и реализацией в рабочем дереве. Атлас не доказывает состояние
production. Команды ниже выполняются из корня репозитория.

Прочитай [правила архитектуры](../../../docs/architecture/README.md) и
[руководство атласа](../../../docs/architecture/explorer/README.md).
При точечной правке читай затронутые контракты, реализацию и `details/*.json`;
не требуется заново исследовать все сервисы.

## Источники и область правки

| Что меняется | Где менять |
|---|---|
| Границы, владельцы данных, инфраструктура | `docs/architecture/model/services.yaml`, связанные accepted ADR |
| HTTP: параметры, схемы, security, ответы | `contracts/openapi/public/<id>.yaml`, контрактные `$ref`, реализация |
| Подключение реализованного сервиса | `backend/services/<id>/service.yaml` |
| Events: producer, consumers, envelope, payload | `docs/architecture/model/events.yaml`, descriptor, producer/consumer |
| Разрешённые синхронные вызовы | `docs/architecture/model/sync-calls.yaml`, descriptor, реализация вызова |
| Пояснения, timeout/TTL/retry, шаги сценария | `docs/architecture/explorer/details/<id>.json` |
| Раскладка и навигация карты | `docs/architecture/explorer/app.js`, `style.css`, `template.html` |
| Извлечение данных и валидация | `docs/architecture/explorer/build.py`, `tests/` |

`data.js` и `index.html` генерируются; не редактируй их вручную. Не меняй
бизнес-поведение только ради соответствия старой подписи в атласе. Если найдена
разница между accepted ADR, моделью и кодом, укажи её явно и исправь в границах
задания; спорное архитектурное решение не маскируй как реализованное.

## Добавление сервиса

1. Согласуй стабильный `id` в модели, имени каталога и descriptor. Генератор
   обнаруживает `backend/services/*/service.yaml` автоматически. Наличие
   descriptor означает статус «реализовано», поэтому не создавай фиктивный
   descriptor для запланированного сервиса.
2. `public_openapi.source` подключает активные операции, `runtime_openapi` —
   probes, закрытые на ingress. `contracts/openapi/planned.yaml` остаётся
   roadmap. Сейчас генератор читает только эти два поля: новый вид контракта,
   например отдельный internal API, требует явной поддержки в `build.py` и
   проверки извлечения операций.
3. Обнови модель и реальные `messaging.publishes` / `messaging.consumes` в
   descriptor с парами `type` + `version`. Субъект строится как
   `cookie.events.<event_type>.v<event_version>`. Готовый consumer не означает
   готовность producer: атлас определяет их статусы отдельно.
4. Добавь `details/<id>.json` с `serviceId`, `facts`, `flows`, `operationNotes`;
   используй минимальный пример из руководства. Не копируй факты Identity или
   Notification, если они не подтверждены новым сервисом.
5. Проверь топологию в браузере. Новые сервисы получают дополнительные узлы из
   модели, связи sync/events появляются при выборе сервиса или сценария.
   Основная раскладка и связи Identity/Notification заданы вручную в
   `baseNodes` / `baseEdges` внутри `app.js`. Автообнаружение не добавляет
   отдельную БД, ingress route или все инфраструктурные стрелки нового сервиса.
   Добавь нужные узлы и связи для фактического пути запроса; для нового
   инфраструктурного alias согласуй `NODE_ALIASES` в `build.py`. Отдельно
   проверь текущий gateway и целевой `api_gateway`, не смешивай их статусы.

## Факты и сценарии

- IDs фактов и сценариев глобально уникальны; используй префикс сервиса.
  Сохраняй существующие IDs при правке, чтобы URL и ссылки продолжали работать.
- Каждый факт и шаг содержит `source: {"path": "...", "line": N}`: путь от
  корня репозитория и точная строка, начиная с 1. После изменения исходника
  найди утверждение заново, а не только исправь номер, вышедший за конец файла.
  Проверка диапазона строк не проверяет смысл подписи.
- Для timeout различай connect/read/request, значение по умолчанию и override
  окружения. Указывай единицы, retry/backoff, лимиты, TTL и поведение ошибки там,
  где это влияет на путь запроса. Неизвестное значение обозначай явно;
  timeout соседнего компонента не является timeout этого запроса.
- `flows[].operationIds` и ключи `operationNotes` ссылаются на активные IDs.
  Public ID равен `operationId`; runtime ID имеет вид `<service>:<operationId>`.
  `operationNotes[ID].flowId` связывает ручку со сценарием.
- `flows[].steps[].node` должен существовать в модели или aliases и реально
  отображаться на карте. Опиши transport, проверку доступа, application,
  транзакцию/БД, publish/consume и внешнюю доставку в необходимой детализации.
  ACK после commit, retry и дедупликацию показывай по реализации.
- `nextFlows` содержит существующие IDs асинхронных продолжений, в том числе
  из другого `details`-файла. Сохраняй переходы при переносе или правке сценария.
  Новая цепочка должна позволять пройти от HTTP до consumer/provider.
- При обновлении сервиса проверь затронутые факты, сценарии и связанные
  сервисы, а не только пересобери снимок. При удалении переезжающих сущностей
  исправь `operationNotes`, `operationIds`, `nextFlows` и топологию.

## Проверка и выдача

```bash
make architecture-build
make architecture-check
```

`make` использует локальный `.cache/architecture-explorer-venv`; глобальные
Python-пакеты не нужны. Проверка включает актуальность обоих артефактов,
тесты генератора, синтаксис JavaScript и UI-тесты. При изменении контрактов
или поведения выполни также проверки соответствующей области из `AGENTS.md`.
В diff должны попасть исходники атласа и оба обновлённых артефакта.

Открой изменённые разделы через работающий локальный preview; если его ещё
нет, используй `make architecture-serve` (`http://127.0.0.1:8099/`). Проверь
разделение и фильтры по сервисам в HTTP, событиях и сценариях, пустую выборку,
режим планов, ссылки на исходники и переход HTTP → сценарий → карта →
асинхронное продолжение. При правке раскладки проверь читаемость на обычной
и узкой ширине. Для новой логики добавь проверку поведения в существующие
тесты, не тест на точное совпадение текста подписи.

Если отдаёшь пользователю ссылку на preview, оставь обслуживающий её сервер
работать; не останавливай его после визуальной проверки. Сам HTML
самодостаточен, а встроенный браузер может требовать HTTP вместо `file://`.
Атлас содержит снимки исходников: не встраивай секреты и не расширяй
разрешённые пути `build.py` ради `.env`, ключей или state. Публикация сайта не
является частью обновления локальной карты.
